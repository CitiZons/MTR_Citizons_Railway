# 普通轨道渲染与存储优化方案

本方案尚未实施。本轮只优化材质包几何；Point Advanced 的普通轨道渲染与存储代码保持现状。

## 1. 明确原生渲染与道岔接管的边界

- 无道岔、无平交的单元，以及没有被当前道岔接管区域覆盖的单元，优先交给 MTR 优化渲染器。
- Point Advanced 只绘制实际替换的道岔、平交、附件及必要的接缝修正。交接位置以完整轨道单元边界确定，不能截断单元或让双方同时绘制。
- 必须同时调整整条资源入口与逐单元回调。目前只放行前者，后者仍会通过 LOD 和枕木调整重新接管轨道。
- 长轨道上只有局部道岔时，应按单元或局部区段交接，避免整个轨道资源仍由模组接管。

MTR 的普通资源声明当前引用最高精度 OBJ，Point Advanced 的三档配置不能自动作用于原生回退。因此需要在保留 MTR 批处理的前提下，为它选择相应的模型资源；直接放行高精度模型不能视作已经完成优化。

## 2. 保留连续性和护轨行为

- 交接两侧使用相同的轨距、轨顶高度和钢轨截面，匹配实际 MTR／Optional Rail 单元端部的切线、坡度和超高。
- 枕木端点对齐、连续护轨鼻端和共享底座各自只能有一个绘制方；交接不能使护轨每隔 0.6 米重复出现端头。
- 补缝仅收集交接边界与真正改变的邻域，不对全场普通轨道反复建立接缝输入。
- 内部钢轨端盖应在单元归属明确后筛除，保留真实轨端及需要封闭的裁剪边界。这一项本轮按要求暂缓。

## 3. 需要保留模组绘制的部分，减少几何副本

- 模型模板共享顶点、UV、法线和索引，使用紧凑数组，减少每面一个 `Quad`、多个集合和装箱浮点数的存储。
- 直轨枕木和扣件共享局部模型，保存位置、朝向、超高和灯光等实例数据；不为每个重复单元保存完整的世界坐标几何。
- 弯曲钢轨及确实需要裁剪的结构在轨道或设置变化时烘焙为分块缓冲。相机转向只影响可见性，不改变缓存内容。
- 缓存按轨道、样式及几何版本失效。删除轨道、改材质和设置变化必须及时更新，不能靠延迟删除来维持画面。
- 若灯光变化成为上传热点，将灯光数据与固定顶点位置分开更新，避免重建整块静态缓冲。

## 4. 实施顺序

先比较相同低精度模型下，现有绘制与 MTR 批处理的帧时间、提交开销和常驻内存；再实施局部交接，最后处理确有必要的存储改造。比较时固定场景、视距、光影和帧率上限，避免把模型差异或设置差异当成管线收益。

本方案不预设 FPS 提升幅度。几何减面、渲染交接和存储改造分开评估，以便定位真正有效的改动。
