# 普通轨道渲染与存储：现状与剩余工作

本文记录 Point Advanced 对普通资源包轨道的接管边界。`0.1.7`—`0.1.11` 已实施按 8 m 区块的普通轨道缓存、逐区块 LOD、局部道床／接缝更新和 GPU 批次复用；尚未把无道岔单元交还 MTR 原生渲染器。以下“剩余工作”是后续方案，不代表当前版本已经实现。

## 1. 当前边界

- 资源包轨道的普通单元仍由 Point Advanced 绘制，包括轨枕、扣件、道床和接缝修正。MTR 原生渲染器只负责未被接管或被明确回退的道岔／异形布局。
- 普通轨道按完整 8 m 空间块缓存，精度按区块选择，并在距离分界附近保留切换余量。世界区块保持加载时，转动视角或离开后返回会复用未变化的几何。
- 床位、接缝补面和局部轨道变化按区域刷新；后台几何准备、每帧上传预算和 GPU 批次复用已经接入。
- 连续护轨的钢轨、端头和承座由独立路径绘制；`0.1.11` 在承座提交时按当前位置重新选择 LOD。

## 2. 尚未实施的交接优化

目标是把没有道岔、平交或必要接缝修正的普通单元优先交还 MTR 优化渲染器，只保留实际替换的道岔、平交、附件及交接边界。

- 交接位置以完整轨道单元边界确定，不能截断单元，也不能让双方同时绘制。
- 必须同时调整整条资源入口和逐单元回调。当前逐单元回调仍会通过 LOD 和枕木调整重新接管轨道；只放行整条资源不足以完成交接。
- 长轨道上只有局部道岔时，应按单元或局部区段交接，避免整条轨道资源仍由模组接管。
- MTR 的普通资源声明当前引用最高精度 OBJ，Point Advanced 的三档配置不能自动作用于原生回退。需要在保留 MTR 批处理的前提下为它选择相应模型资源；直接放行高精度模型不能视作已经完成优化。

## 3. 连续性约束

- 交接两侧使用相同的轨距、轨顶高度和钢轨截面，匹配实际 MTR／Optional Rail 单元端部的切线、坡度和超高。
- 枕木端点对齐、连续护轨鼻端和共享底座各自只能有一个绘制方；交接不能使护轨每隔 0.6 米重复出现端头。
- 补缝只收集交接边界与真正改变的邻域，不对全场普通轨道反复建立接缝输入。
- 内部钢轨端盖应在单元归属明确后筛除，保留真实轨端及需要封闭的裁剪边界；这一项仍未实施。

## 4. 存储改造（未实施）

- 模型模板共享顶点、UV、法线和索引，使用紧凑数组，减少每面一个 `Quad`、多个集合和装箱浮点数的存储。
- 直轨枕木和扣件共享局部模型，保存位置、朝向、超高和灯光等实例数据；不为每个重复单元保存完整的世界坐标几何。
- 弯曲钢轨及确实需要裁剪的结构在轨道或设置变化时烘焙为分块缓冲。相机转向只影响可见性，不改变缓存内容。
- 缓存按轨道、样式及几何版本失效。删除轨道、改材质和设置变化必须及时更新，不能靠延迟删除来维持画面。
- 若灯光变化成为上传热点，将灯光数据与固定顶点位置分开更新，避免重建整块静态缓冲。

## 5. 评估顺序

先比较相同低精度模型下，现有绘制与 MTR 批处理的帧时间、提交开销和常驻内存；再实施局部交接，最后处理确有必要的存储改造。比较时固定场景、视距、光影和帧率上限，避免把模型差异或设置差异当成管线收益。

本方案不预设 FPS 提升幅度。几何减面、渲染交接和存储改造分开评估，以便定位真正有效的改动。现有验证只覆盖缓存复用、局部更新和几何正确性，尚无同场景版本间 FPS／内存对照数据。
